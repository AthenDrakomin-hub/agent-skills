## 模块依赖图

用文本或 Mermaid 表示模块间依赖关系：

```mermaid
graph TD
    A[模块1: 数据模型] --> B[模块2: 工具函数]
    B --> C[模块3: 网络通信]
    C --> D[模块4: 业务逻辑]
    D --> E[模块5: API接口]
```

无依赖的底层模块先实现，被依赖多的模块优先保证质量。

## 拆解质量检查

- [ ] 每个 P0 模块都有明确的输入输出
- [ ] 模块间依赖无循环
- [ ] 每个模块都有对应的逆向证据
- [ ] P0 模块构成最小可运行版本
- [ ] 没有遗漏原始软件的核心功能
- [ ] 复杂度评估合理（高复杂度模块考虑进一步拆分）
- [ ] 用户已确认模块范围和优先级
