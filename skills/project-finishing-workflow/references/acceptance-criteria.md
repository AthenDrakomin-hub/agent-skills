# 项目交付验收标准

> 可机器判定的验收标准，用于 Step 4 独立验收阶段。配合 `scripts/acceptance-check.py` 和 `scripts/verify-all.sh` 使用。

## 验收等级

| 等级 | 含义 | 交付条件 |
|---|---|---|
| **P0 必须通过** | 不通过不能交付 | 全部 ✅ |
| **P1 应该通过** | 不通过需说明原因 | 全部 ✅ 或有明确的延期计划 |
| **P2 建议通过** | 不通过可交付但需记录 | 记录为已知问题 |

---

## 一、P0 必须通过项

### 1.1 构建与测试
- [ ] **构建成功**：`npm run build` / `mvn package` / `go build` 退出码为 0
- [ ] **测试全绿**：所有测试用例通过，退出码为 0
- [ ] **Lint 通过**：ESLint/flake8/go vet 无 error
- [ ] **无编译错误**：TypeScript tsc --noEmit 无错误

### 1.2 安全
- [ ] **无硬编码密钥**：代码中无 API Key/密码/Token
- [ ] **.env 被忽略**：.gitignore 包含 .env
- [ ] **无敏感文件提交**：git log 中无 .env/密钥文件

### 1.3 功能
- [ ] **核心功能可用**：主流程能正常走通
- [ ] **无 P0 Bug**：无导致系统崩溃/数据丢失的 Bug
- [ ] **错误处理**：关键操作有错误提示，不白屏

### 1.4 文档
- [ ] **README 存在**：包含安装、运行、部署说明
- [ ] **.gitignore 存在**：忽略 node_modules、.env、构建产物

---

## 二、P1 应该通过项

### 2.1 测试质量
- [ ] **测试覆盖率 > 70%**：核心模块 > 80%
- [ ] **有集成测试**：关键路径有端到端测试
- [ ] **无 flaky test**：测试连续运行 3 次都通过

### 2.2 代码质量
- [ ] **无 TODO/FIXME**：或已记录到 issue tracker
- [ ] **无调试代码**：无 console.log/print/debugger
- [ ] **无大文件**：单个文件 < 500 行（或有拆分计划）
- [ ] **命名规范**：变量/函数/组件命名一致且有意义

### 2.3 性能
- [ ] **首屏加载 < 3s**：在 4G 网络下
- [ ] **无明显卡顿**：交互响应 < 100ms
- [ ] **无内存泄漏**：长时间运行内存稳定

### 2.4 兼容性
- [ ] **主流浏览器**：Chrome/Safari/Firefox/Edge 最新版
- [ ] **移动端适配**：375px 宽度下布局正常
- [ ] **响应式**：常见分辨率下布局正常

### 2.5 部署
- [ ] **部署脚本可用**：一键部署或有详细文档
- [ ] **环境变量清单**：所有需要的环境变量已列出
- [ ] **回滚方案**：有明确的回滚步骤
- [ ] **健康检查**：有 /health 或类似端点

---

## 三、P2 建议通过项

### 3.1 文档完善
- [ ] **CHANGELOG 已更新**
- [ ] **API 文档完整**
- [ ] **FAQ 已整理**
- [ ] **贡献指南（CONTRIBUTING.md）**

### 3.2 监控与运维
- [ ] **错误监控**：Sentry 或类似工具已接入
- [ ] **性能监控**：有性能数据采集
- [ ] **日志收集**：有集中式日志
- [ ] **告警机制**：关键指标异常有告警

### 3.3 工程化
- [ ] **CI/CD 流水线**：自动测试+构建+部署
- [ ] **代码审查**：有 PR review 流程
- [ ] **分支策略**：有明确的分支管理规范
- [ ] **版本管理**：语义化版本号

## 验收流程

### Step 1: 自动化检查（必须）

```bash
# 1. 运行缺口扫描
python3 scripts/gap-scan.py . --output gap-report.md

# 2. 运行全量验证
bash scripts/verify-all.sh .

# 3. 运行验收检查
python3 scripts/acceptance-check.py . --output acceptance-report.md
```

三个脚本都必须退出码为 0（或无 Critical 问题）。

### Step 2: 人工验收（必须）

1. 对照本清单逐项检查
2. 模拟真实用户操作（乱点、异常输入、边界场景）
3. 检查 P0 项全部通过
4. P1 项不通过的需说明原因和延期计划

### Step 3: 验收报告

输出格式：

```
## 验收结论
✅ 可以交付 / ❌ 暂不可交付

## P0 检查结果
- [x] 构建成功
- [x] 测试全绿
- [ ] 无硬编码密钥（发现 2 处，已修复）

## P1 检查结果
- [x] 测试覆盖率 78%
- [ ] 无 TODO（剩余 3 个，已记录到 issue #123）

## 已知问题
1. xxx（P2，计划 v1.1 修复）

## 遗留风险
1. xxx
```

## 常见不通过原因及修复

| 不通过项 | 常见原因 | 修复方法 |
|---|---|---|
| 构建失败 | 依赖缺失、类型错误 | 修复报错，重新构建 |
| 测试失败 | 代码变更未更新测试 | 修复测试或代码 |
| 硬编码密钥 | 开发时图方便 | 移到环境变量，轮换已泄露的密钥 |
| .env 未忽略 | 忘记加 .gitignore | 添加到 .gitignore，从 git 历史中移除 |
| 测试覆盖率低 | 只写了 happy path | 补充边界和异常测试 |
| 无 README | 觉得"代码自解释" | 写最小可用 README |
| 移动端适配差 | 只在桌面端测试 | 用 DevTools 移动端模式检查 |

---

## 验收通过标准

- **P0 全部通过** → 可以交付
- **P0 全过 + P1 ≥ 80% 通过** → 高质量交付
- **P0 全过 + P1 全过 + P2 ≥ 50%** → 优秀交付
