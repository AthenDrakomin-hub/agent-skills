# 阶段M：收尾验收提示词

> 适用场景：所有模块开发完后，开新对话让 AI 站在验收者角度列出缺口清单（不改代码）

## 缺口盘点提示词

```
你是一位独立的软件验收专家。你不修改任何代码，只负责找出当前项目所有影响交付的问题。

## 项目背景
[粘贴：项目完整需求清单 + 技术方案 + 完整目录结构]

## 任务：缺口盘点（不改代码）
对照需求清单，逐项检查以下容易被遗漏的场景：
1. 输入为空、超长、特殊字符
2. 重复点击、并发操作、快速切换
3. 刷新数据、导入导出、恢复备份
4. 错误提示是否友好
5. 数据边界（大数据量、长文本）
6. 是否有TODO/FIXME残留
7. 是否有死代码、未使用的变量
8. 是否有明显的逻辑漏洞

## 输出格式
生成《收尾缺口清单》，每条包含：
- [编号] 问题描述
- 严重程度（🔴致命 / 🟡严重 / 🟢轻微）
- 复现步骤（如适用）
- 修复建议
- 预计修复时间
```

## 单个 Bug 修复提示词（每个缺口开新对话）

```
你是资深工程师。我的项目有一个bug需要修复。

## 项目背景
[粘贴：相关代码片段 + 问题描述]

## 这个bug
[粘贴：问题描述、复现步骤、报错信息]

## 修复要求
1. 先说明你判断的根因
2. 给出修复后的完整代码（只改相关部分）
3. 说明如何验证修复有效
4. 提醒我是否有其他代码可能受此修改影响
```

## 你的动作

1. 拿到缺口清单后，**逐个在本地验证确认**（AI 看不到你电脑，它列的可能不准确）
2. 确认是真实问题后，对每个缺口**开新对话**单独修复
3. 修一个、验一个，全绿才下一个

## 缺口严重程度处理建议

| 严重程度 | 处理方式 |
|---|---|
| 🔴 致命 | 必须修复，否则不能交付 |
| 🟡 严重 | 应该修复，影响核心体验 |
| 🟢 轻微 | 可修复，也可记录为已知问题后续迭代 |

## 产出物检查清单

- [ ] 缺口清单已逐条本地验证
- [ ] 🔴致命问题全部修复
- [ ] 🟡严重问题全部修复
- [ ] 每个修复都经过本地验证
- [ ] 没有引入新的回归问题
