# 阶段1：搭骨架代码提示词

> 适用场景：开新对话，让 AI 生成项目初始化代码（配置、入口、主结构），能跑起来即可

## 提示词模板

```
你是资深[前端/后端]工程师。基于我确认的项目方案，先生成项目的骨架代码。

## 项目背景（重新交代，因为新对话它不记得）
[粘贴阶段0确认的需求清单和技术方案，或简要复述]

## 这次只做"骨架"（不要写完整功能）
1. 生成项目的基础结构：配置文件、入口文件、主框架
2. 把模块的占位骨架写好（函数/类先定义，逻辑可留空）
3. 让项目能"跑起来"，哪怕只有一个空页面/空接口

## 输出要求
- 直接输出完整代码，不要用"此处略去"等写法
- 每个文件注明文件名和保存位置
- 告诉我怎么运行（命令行步骤）

## 特别提醒
- 如果代码太长一次写不完，分文件多次输出，我会逐个保存
- 不要跳过任何基础配置，我要能真正运行起来
```

## 本地验证循环

```
① 保存AI输出的代码 → ② 按AI说的方式启动项目
③ 报错？ → 把报错信息原样贴回去 → AI修 → ①再循环
④ 项目能跑起来 → 进入阶段2
```

## 常见报错及应对

| 报错类型 | 应对方式 |
|---|---|
| 依赖缺失 | 把完整报错贴回去，让它补安装命令 |
| 配置错误 | 把配置文件内容+报错一起贴回去 |
| 端口占用 | 告诉它端口被占，让它改端口或给解决命令 |
| 版本不兼容 | 告诉它你的 Node/Python 版本，让它调整 |

## 产出物检查清单

- [ ] 项目能在本地启动（无报错）
- [ ] 能看到空页面/空接口响应
- [ ] 所有配置文件齐全
- [ ] 模块占位骨架已定义（函数/类名清晰）
- [ ] 你知道怎么启动和停止项目
