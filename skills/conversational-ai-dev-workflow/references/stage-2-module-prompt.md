# 阶段2~N：逐个模块开发提示词

> 适用场景：每个模块开一个新对话，贴背景+已有代码骨架，让 AI 生成该模块

## 提示词模板（每开发一个模块用一次）

```
你是资深[前端/后端]工程师。请为我的项目实现一个具体模块。

## 项目背景（每次都要交代，因为新对话它不记得）
[粘贴：项目是什么、用的什么技术栈]

## 已有代码骨架（关键！贴给它看）
以下是我的项目当前结构，请先理解再写：

[粘贴：项目目录结构，以及与本模块相关的已有代码]

## 本次要实现的模块
[模块名]：实现[功能描述]

## 需求与验收标准
[从阶段0的需求清单中，粘贴本模块对应的需求条目和验收标准]

## 输出要求
- 直接输出完整代码，不要用"此处略去"等写法
- 只修改与本模块相关的文件，不擅自改动其他模块
- 告诉我新增/修改了哪些文件，以及如何测试
- 如果与其他模块有接口依赖，明确说明约定

## 禁止事项
- 不要擅自改变已经确认的技术方案
- 不要跳过任何我要求的验收标准
- 不要用"大概、应该"这类词，说清楚你做了什么
```

## 本地验证循环（每轮）

```
① 保存AI输出的代码 → ② 在本地运行/集成测试
③ 有报错？ → 把报错原样贴给AI → AI修 → ①再循环
④ 功能通过 → 进入下一个模块（开新对话）
```

## 贴代码的技巧

1. **只贴相关的**：不要把整个项目都贴进去，只贴与本模块相关的文件
2. **贴目录结构**：先贴 `tree` 输出，让它知道整体结构
3. **贴接口约定**：如果模块间有依赖，把已有的接口/函数签名贴给它
4. **贴报错全文**：报错要原样粘贴，不要自己总结或省略

## 模块拆分建议

| 项目类型 | 建议模块划分 |
|---|---|
| 前端单页应用 | 页面骨架 → 数据层 → 各功能页面 → 交互细节 → 样式优化 |
| 后端API | 项目骨架 → 数据模型 → 各路由模块 → 中间件 → 错误处理 |
| 全栈应用 | 后端骨架 → 前端骨架 → 各业务模块（前后端一起）→ 联调 |
| 工具脚本 | 主入口 → 核心功能函数 → 参数解析 → 输出格式化 |

## 产出物检查清单（每个模块）

- [ ] 模块代码已保存到正确位置
- [ ] 本地运行无报错
- [ ] 验收标准全部通过
- [ ] 未破坏已有模块功能
- [ ] 与其他模块的接口约定已明确
