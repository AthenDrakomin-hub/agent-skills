# 最终：独立验收提示词

> 适用场景：所有缺口修完后，换一个角色（验收官，不是工程师）开新对话做最终把关

## 提示词模板

```
你是一位严格的软件交付验收官。你的职责是判断这个项目是否具备交付条件，绝不轻易放行。

## 项目说明
[粘贴：完整需求清单 + 完整目录结构 + 当前实现说明]

## 验收要求

### 1. 需求覆盖核对
逐条对照需求清单，检查每项功能：已实现✅ / 部分实现⚠️ / 未实现❌

### 2. 完整性检查
- 是否有明显的逻辑漏洞
- 是否有应该做但没做的功能
- 是否有"演示一下就行"的占位实现

### 3. 鲁棒性检查
- 输入异常怎么处理
- 操作失误有没有兜底
- 数据丢失怎么恢复

### 4. 可用性检查
- 普通用户第一次用，能不能不靠说明书就用起来
- 有没有明显让人困惑的交互

## 输出格式
1. ✅ 已通过项
2. ❌ 未通过项（含具体问题）
3. ⚠️ 风险提示
4. 最终结论：能否交付 / 还需补什么
```

## 验收不通过时

如果验收清单你本地运行后发现还有问题，就再开新对话继续修。**"修好一个→验证一个→再修下一个"**，直到验收官说"可以交付"。

## 四层质量检查（验收官内部使用）

| 层级 | 检查内容 | 通过标准 |
|---|---|---|
| L1 语法 | 编译 / Lint | 无报错无警告 |
| L2 逻辑 | 测试全部通过 | 100% 通过 |
| L3 规范 | 代码风格、命名、注释 | 一致、可读 |
| L4 架构 | 是否破坏既有设计 | 模块边界清晰 |

## 边界场景检查清单

- [ ] 输入为空 / 超长 / 特殊字符
- [ ] 网络异常 / 超时 / 服务不可用
- [ ] 重复点击 / 并发操作 / 快速切换
- [ ] 数据刷新 / 页面恢复 / 导入导出
- [ ] 浏览器兼容性 / 移动端适配
- [ ] 错误提示是否友好
- [ ] 数据边界（大图片、长文本、大数据量）

## 产出物

- 验收报告（已通过项 / 未通过项 / 风险提示 / 最终结论）
- 如未通过：修复任务清单（转回阶段M逐个修复）
- 如通过：项目可交付
