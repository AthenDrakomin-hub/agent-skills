# 对照验证清单

复刻代码完成后，按此清单逐项验证。验证的核心原则是：**用原始软件的行为作为标准答案，测试复刻版本是否一致。**

---

|------|---------|--------|------|------|--------|
| `<模块1>` | | | | | |
| `<模块2>` | | | | | |

**要求**：P0 模块测试覆盖率 ≥ 80%，核心函数覆盖率 100%。

### 1.2 测试用例来源

每个测试用例必须标注来源：

| 来源类型 | 说明 | 示例 |
|---------|------|------|
| 逆向观察 | 从 REA 分析中直接观察到的输入输出 | 原始函数 0x180045A0 输入 0.5 返回 -0.3 |
| 边界推断 | 根据伪代码逻辑推断的边界值 | 循环上限、空指针、除零 |
| 规范推导 | 根据协议/格式规范推导 | 网络包长度字段最大值 |
| 随机生成 | 对纯计算函数用随机值做属性测试 | 加密-解密往返一致性 |

## 二、行为对照验证

### 2.1 核心路径对照

对每条核心业务路径，构造相同输入，对比原始软件和复刻版本的输出：

| 测试场景 | 输入 | 原始软件输出 | 复刻版本输出 | 一致 | 备注 |
|---------|------|------------|------------|------|------|
| `<场景1>` | | | | ✅/❌ | |
| `<场景2>` | | | | ✅/❌ | |

**一致率要求**：核心路径 ≥ 95%。

### 2.2 对照测试方法

根据目标类型选择可行的对照方法：

| 目标类型 | 对照方法 |
|---------|---------|
| 原生二进制（有程序） | 编写 harness 调用原始函数，对比输出 |
| 原生二进制（无程序/仅库） | 从伪代码推导预期值，人工验证 |
| JavaScript/Electron | 直接运行原始 JS 函数，对比输出 |
| 网站/Web 应用 | 相同请求对比响应（注意时间戳/随机数需排除） |
| Android APK | 模拟器运行原始 APP，对比行为 |
| .NET | 反射调用原始程序集，对比输出 |

### 2.3 不一致处理流程

发现不一致时：

```
1. 记录不一致的输入和双方输出
2. 检查复刻代码的逻辑翻译是否有偏差
   ├─ 变量映射错误？
   ├─ 边界条件遗漏？
   ├─ 类型转换差异？
   └─ 算法理解错误？
3. 如复刻代码无误，回到 STEP 3 对相关函数做更深入逆向分析
   ├─ 是否有未发现的代码路径？
   ├─ 是否有全局状态影响？
   └─ 是否有外部依赖（时间、随机数、系统调用）？
4. 修正后重新测试
5. 记录修正原因和新增的逆向证据
```

连续 3 轮修正后仍不一致的核心路径，停止自动修正，报告差异并建议人工复核。

## 三、边界与异常测试

### 3.1 输入边界

| 测试类型 | 测试内容 | 通过标准 |
|---------|---------|---------|
| 空值 | null/undefined/空字符串/空数组 | 不崩溃，返回合理错误或默认值 |
| 极值 | 最大/最小值、超长字符串、超大数组 | 行为与原始一致或合理降级 |
| 类型错误 | 错误类型输入 | 有参数校验，抛出明确错误 |
| 格式错误 | 非法格式数据（如坏 JSON、坏图片） | 优雅处理，不崩溃 |

### 3.2 状态边界

| 测试类型 | 测试内容 |
|---------|---------|
| 初始状态 | 首次启动/首次调用的行为 |
| 状态转换 | 所有状态机转换路径 |
| 并发/竞态 | 多线程/多请求同时操作（如涉及） |
| 资源耗尽 | 内存不足、磁盘满、网络断开（如涉及） |

### 3.3 安全测试（复刻项目必要）

| 测试项 | 检查内容 |
|--------|---------|
| 输入校验 | 所有外部输入有校验，无注入风险 |
| 敏感数据 | 密钥/密码不硬编码，不在日志中明文输出 |
| 权限边界 | 未授权访问被拒绝 |
| 依赖漏洞 | 第三方依赖无已知高危漏洞 |

### 5.3 文档

- [ ] 模块拆解文档完整
