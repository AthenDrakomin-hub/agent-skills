# 逆向复刻工作流指南

本指南覆盖从"看懂逆向分析结果"到"交付一套可运行复刻代码"的完整过程。

## 核心理念

复刻的目标是**功能等价**，不是代码复制。你是在理解原始软件的行为逻辑后，用自己的技术栈独立重实现。

```
逆向分析 → 理解行为 → 模块拆解 → 技术栈映射 → 独立重实现 → 对照验证 → 迭代修正
```

## 第一阶段：从分析报告到模块清单

### 1.1 提取功能点

通读 STEP 4 的分析报告，将"关键发现"转化为可复刻的功能点：

| 分析报告中的发现 | 转化为 |
|-----------------|--------|
| 发现了一个加密函数 | 模块：数据加密（输入明文→输出密文） |
| 发现了 API 端点和请求格式 | 模块：网络通信（接口定义+请求签名） |
| 发现了状态机逻辑 | 模块：状态管理（状态转换规则） |
| 发现了 UI 交互流程 | 模块：前端交互（页面流转+事件处理） |
| 发现了数据存储结构 | 模块：数据持久化（表结构+读写逻辑） |

### 1.2 识别核心路径

核心路径（P0）是软件"没有它就不能用"的功能：
- 用户登录/认证
- 主业务流程（如聊天软件的消息收发、游戏的核心玩法）
- 数据加载和保存

边缘功能（P2）是锦上添花：
- 设置页面的高级选项
- 主题切换
- 帮助/关于页面

### 1.3 绘制依赖关系

用简单的依赖图表示模块间关系：

```
[用户认证] ← [会话管理] ← [消息收发] ← [消息存储]
                ↓
           [网络通信层]
```

先实现无依赖或依赖少的底层模块，再实现上层业务模块。

## 第二阶段：技术栈映射

### 2.1 语言映射原则

| 原始实现 | 映射到用户技术栈时 |
|---------|-------------------|
| C 函数 | 后端语言的函数/方法，保持参数和返回值语义 |
| C++ 类 | 后端语言的类，方法名可重命名但行为不变 |
| 汇编伪代码 | 先理解算法逻辑，再用高级语言重写（不要逐行翻译汇编） |
| JavaScript | 可直接参考逻辑，按用户前端框架重构组件 |
| Java/Kotlin | 映射到后端语言，注意 JVM 特有概念（如反射、注解）的替代 |
| CIL (.NET) | 映射到对应语言，注意 IL 指令的高级语言等价物 |
| Smali (Android) | 先理解为 Java 逻辑，再映射到目标语言 |

### 2.2 数据结构映射

| 原始结构 | 通用替代 |
|---------|---------|
| C struct | 后端语言的 class/struct/dataclass |
| C 指针 | 引用/对象（注意空指针检查） |
| 固定大小数组 | 动态数组/列表（如逻辑依赖固定大小则保留） |
| 位域 (bitfield) | 整数 + 位运算常量 |
| 联合体 (union) | 带类型标签的类或序列化处理 |
| char* 字符串 | 目标语言的字符串类型 |

### 2.3 算法翻译

1. **先理解再翻译**：读伪代码，用自然语言写出算法步骤，然后用目标语言实现
2. **保留边界条件**：原始代码中的 `if (x == 0)`、`for (i=0; i<len; i++)` 等边界必须保留
3. **异常处理**：原始代码的错误码/返回值 → 目标语言的异常/Result 类型
4. **常量提取**：魔法数字提取为命名常量，标注来源（逆向证据地址）

### 2.4 禁止事项

- ❌ 直接复制粘贴原始反编译代码（即使是 JS 也要重构）
- ❌ 保留原始变量名（如 `v1`, `v2`, `a3`），必须重命名为有意义的名称
- ❌ 复制原始 UI 资源文件（图片、字体、音频）
- ❌ 复制原始配置文件中的密钥/证书（用自己的替代）

## 第三阶段：逐模块实现

### 3.1 实现顺序

1. **数据模型层**：定义所有数据结构、常量、枚举
2. **工具/工具函数层**：加密、编码、格式化等无状态函数
3. **基础设施层**：网络通信、数据存储、日志
4. **业务逻辑层**：核心业务规则和状态管理
5. **接口/UI 层**：API 端点、页面组件、交互逻辑

### 3.2 代码标注规范

每个复刻的函数/方法必须在注释中标注来源：

```python
def calculate_pan(sound_position: float, listener_x: float) -> float:
    """
    计算声音左右声道平衡。

    复刻自: 原始二进制 0x180045A0 处函数 (DX-Ball 案例)
    证据: 分析报告发现 #3 - 声音位置到 pan 值的转换逻辑
    原始逻辑: pan = (position - listener_x) / max_distance, clamp to [-1, 1]
    """
    # 实现...
```

### 3.3 增量交付

- 每完成一个 P0 模块，立即写单元测试并运行
- 不要等所有模块写完再测试
- 每完成一组相关模块，做一次集成测试
- 随时可以向用户展示当前可运行的最小版本

## 第四阶段：资源与配置

### 4.1 常量与配置

从逆向结果中提取的常量：
- 协议版本号、端口号、超时时间 → 配置文件
- 加密密钥、盐值 → **必须替换为自己的**，不得使用原始值
- API 端点路径 → 配置文件（域名替换为自己的）
- 枚举值、状态码 → 代码中的常量/枚举

### 4.2 第三方依赖

识别原始软件使用的第三方库，在用户技术栈中选择等价替代：

| 原始依赖 | 常见替代 |
|---------|---------|
| OpenSSL | 目标语言的标准加密库 |
| libcurl | 目标语言的 HTTP 客户端 |
| SQLite | 同（跨平台） |
| React/Vue | 按用户前端框架选择 |
| FFmpeg | 同（跨平台） |

## 第五阶段：常见复刻陷阱

| 陷阱 | 表现 | 解决 |
|------|------|------|
| 字节序差异 | 网络协议解析错误 | 明确标注大端/小端，测试时验证 |
| 浮点精度 | 计算结果与原始有微小差异 | 确认原始使用的精度（float/double），对照测试用 epsilon 比较 |
| 时间处理 | 时区/时间戳不一致 | 统一使用 UTC，明确时间戳单位（秒/毫秒） |
| 编码问题 | 字符串乱码 | 确认原始编码（UTF-8/GBK/UTF-16），转换时保留 |
| 隐式类型转换 | C 语言的整数溢出/截断行为不同 | 显式处理类型转换，测试边界值 |
| 静态初始化顺序 | C++ 全局对象初始化依赖 | 改为显式初始化函数 |
| 线程安全 | 原始代码的竞态条件 | 分析原始同步机制，用目标语言的并发原语重实现 |

## 复刻完成的定义

- [ ] P0 模块全部实现且可运行
- [ ] 核心路径有端到端测试通过
- [ ] 每个函数标注了逆向证据来源
- [ ] 无原始代码/资源的直接复制
- [ ] 密钥/证书等敏感信息已替换
- [ ] 代码符合用户项目的编码规范
- [ ] 明确列出未复刻的 P1/P2 功能
